| 项 | 内容 |
|---|---|

## 1. 被测对象

| 接口 | 方法 | 说明 |
|---|---|---|
| `/ping` | GET | 健康检查，返回 `"pong"` |
| `/auth` | POST | 账号换 token，成功 200、密码错 401 |
| `/booking` | GET | 预订列表（只返回 id） |
| `/booking` | POST | 创建预订，需 token，校验失败 400 |
| `/booking/{id}` | GET | 查详情，不存在 404 |
| `/booking/{id}` | PUT | 全量更新，需 token，不存在 404、校验失败 400 |
| `/booking/{id}` | PATCH | 局部更新，只改提交的字段 |
| `/booking/{id}` | DELETE | 删除，成功 201、重复删除 404 |
| `/rooms` | GET | 各房型剩余库存 |
| `POST /booking?roomtype=` | — | 创建时扣减对应房型库存，售罄 409 |
| `GET /booking?page=&size=&roomtype=` | — | 分页信封（`items/total/page/size`）或按房型过滤 |
| `/` | GET | 预订管理页面（登录 / 新建 / 改价 / 删除） |

存储是内存字典 + 一把锁，不依赖数据库；服务端口用 `0` 由系统分配。

## 2. 测试范围

**范围内**

- 接口功能：健康检查、鉴权、CRUD 全生命周期
- 参数校验：缺字段、类型错、格式错、业务规则（日期先后、价格范围）
- 契约：响应字段的类型结构（防止后端悄悄改类型）
- 角色权限：admin / viewer，viewer 的写操作必须 403 且数据不变
- 分页与过滤：首页 / 中间页 / 末页不满 / 越界页 / 非法 size / 按房型过滤
- 库存：扣减、售罄 409、删除退还、并发不超卖
- 幂等：同一 `Idempotency-Key` 重复 / 并发提交只建一单
- 性能：并发梯度（1/5/20/50）下的 p50/p95/p99 与吞吐，阈值判定
- 并发：多线程同时创建 / 读取 / 更新 / 删除
- UI 主流程：登录 → 创建 → 改价 → 删除，以及后端报错的前端展示
- 静态检查：语法、硬编码凭据、可变默认参数等

**范围外（明确不测，避免"什么都想测"）**

- 性能压测（只做了延迟冒烟：健康检查中位延迟 < 200ms）
- 安全渗透（没做注入、暴力破解、token 过期）
- 持久化（内存存储，重启即清空）
- 多浏览器兼容（只跑 Chromium）、移动端适配
- 高并发压测（10 线程量级，不是 capacity 测试）

**为什么这么分**：越往下越便宜、反馈越快。静态检查 1 秒内跑完，能拦语法错；冒烟 0.5 秒，能拦服务挂；全量 3 秒；UI 层 3 秒但要浏览器。CI 里按这个顺序阻断，前面挂了就不浪费后面的时间。

## 4. 测试设计方法

### 4.1 等价类划分

把输入分成"行为应当相同"的集合，每个集合挑代表值来测：

| 字段 | 有效等价类 | 无效等价类 | 对应用例 |
|---|---|---|---|
| `firstname` / `lastname` | 非空字符串（中文、英文） | 空串、纯空格、缺失 | 缺 firstname、缺 lastname、数据驱动"名称为空"、`test_negative_price_is_rejected` 等 |
| `totalprice` | 正整数、0、小数 | 字符串、`null`、数组、**负数** | `test_totalprice_must_be_number`（参数化 3 个）、数据驱动"价格为0"、`test_negative_price_is_rejected` |
| `depositpaid` | `true` / `false` | `"yes"`、`1`、`null`、缺失 | `test_depositpaid_must_be_boolean`（参数化 3 个）、数据驱动"缺 depositpaid" |
| `bookingdates` | 合法 ISO 日期且入住 < 退房 | 格式错、非法日期、住 0 晚、入住晚于退房、缺键 | `test_bookingdates_must_be_iso`（3 个）、数据驱动"日期不合法"、`test_same_day_...`、`test_leap_day_boundary` |
| token | 正确 Bearer、正确 Cookie | 缺失、错误值 | `test_create_without_token_is_forbidden`、`test_create_with_wrong_token_is_forbidden` |

> **等价类分析的实战价值**：`totalprice` 的"负数"这个无效类一开始没有用例，补上后立刻抓到 BUG-004（负数价格能创建）。

### 4.2 边界值分析

等价类取中间值，边界值取"刚好越界"的点：

| 被测项 | 边界点 | 期望 | 用例 |
|---|---|---|---|
| 价格 | `-1` / `0` / `1` | 400 / 200 / 200 | `test_negative_price_is_rejected`、数据驱动"价格为0" |
| 日期先后 | `checkin == checkout` / `checkout = checkin + 1天` | 400 / 200 | `test_same_day_...`、正常用例 |
| 闰年 | `2028-02-29`（存在）/ `2026-02-29`（不存在） | 200 / 400 | `test_leap_day_boundary` |
| 姓名 | `""` / `" "` / `"a"` | 400 / 400 / 200 | 数据驱动"名称为空"、UI 空名字用例 |
| 并发数量 | 0 条 / 30 条 | 空列表 / 不丢数据 | `test_concurrent_creates_are_all_stored` |

### 4.3 判定表（创建预订的校验优先级）

`validate()` 是按顺序返回**第一条**错误，所以"多个字段同时错"时，报哪个错要有明确预期：

| 规则序 | 条件 | 命中时返回 | 用例 |
|---|---|---|---|
| 1 | body 不是 JSON 对象 | `body 必须是 JSON 对象` | 空请求体 / 数组 body |
| 2 | 缺 `BOOKING_FIELDS` 中任一字段 | `缺少字段 xxx` | 缺 firstname / 缺 lastname |
| 3 | `bookingdates` 缺 checkin 或 checkout | `bookingdates 需要 checkin 与 checkout` | `test_bookingdates_missing_keys_returns_400` |
| 4 | 日期不匹配 `YYYY-MM-DD` | `bookingdates.xxx 要写成 YYYY-MM-DD` | `test_bookingdates_must_be_iso` |
| 5 | 名字为空（去空格后） | `xxx 不能为空` | 数据驱动"名称为空" |
| 6 | 日期不是真实日期 | `bookingdates 里的日期不是合法日期` | 数据驱动"日期不合法" |
| 7 | checkout ≤ checkin | `退房日期必须晚于入住日期` | `test_same_day_...` |
| 8 | `depositpaid` 非布尔 | `depositpaid 必须是布尔值` | `test_depositpaid_must_be_boolean` |
| 9 | `totalprice` 非数字 | `totalprice 必须是数字` | `test_totalprice_must_be_number` |
| 10 | `totalprice` 为负 | `totalprice 不能是负数` | `test_negative_price_is_rejected` |

### 4.4 状态迁移

```
不存在 ──创建(POST)──▶ 存在 ──PUT/PATCH──▶ 存在(已更新)
  ▲                     │
  │                     └──删除(DELETE)──▶ 不存在
  └─────────────────────────────────────────┘
```

| 非法迁移 | 期望 | 用例 |
|---|---|---|
| 查不存在的 id | 404 | `test_get_unknown_booking_returns_404` |
| 更新不存在的 id | 404 | `test_update_unknown_booking_returns_404` |
| 重复删除 | 404 | `test_delete_twice_returns_404` |
| 删完再查 | 404 | `test_deleted_booking_is_gone` |

## 7. 准入 / 退出准则

**准入**：代码能通过 `compileall`；本地 mock 能起、`/ping` 返回 200。

**退出（全部满足才算测完）**

1. 冒烟 4 条全绿；
2. 接口全量用例全绿（允许 3 条模板用例 skip）；
3. 契约快照无未确认改动，且 JSON Schema 用例全绿；
4. 并发用例全绿，且没有靠重试才变绿的用例；
5. 语句覆盖率 ≥ 90%（CI 门槛 `coverage_simple.py --min 90`，当前 95.0%）；
6. UI 层 6 条全绿（本机或 CI 第 4 关）；
7. 没有"高"级别的静态检查问题（当前 0 条；注意扫描器只检查变量赋值形式的硬编码凭据，mock 的账号表是字典字面量，属于已知盲区）。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| mock 的固定 token 是明文 | 真实项目里属于严重问题 | 这是本地靶场，README 已说明；换真实服务时改环境变量 |
| 只测了 Chromium | 其他浏览器可能布局/事件不同 | 需要时 `playwright install firefox webkit` 并改 `browser` 夹具 |
| 并发用例的 10 线程量级小 | 发现不了高并发下的性能问题 | 明确列为范围外；写清"这不是压测" |
| UI 用例依赖页面元素 id | 前端改结构会导致用例红 | 用例只用稳定 id，不用层级选择器；改结构时同步改用例 |
| 断言的错误文案是中文 | 文案一改用例就红 | 断言只校验关键子串（如"不能为空"），不校验整句 |
